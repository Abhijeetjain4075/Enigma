# Enigma Deep Audit v2 — 2026-09-30

## Audit scope

This v2 audit rechecks the live GitHub repository, its complete tracked tree, architecture documents, transaction model, standards baseline, competitive assumptions, security/privacy model, regulatory assumptions, operating model, and research process against fresh primary web evidence.

This is not a claim of literal worldwide exhaustiveness. The correct engineering response to an unbounded "everything" requirement is a continuously versioned evidence system with explicit confidence, provenance, and revalidation.

## New high-priority findings

### 1. Regulatory data is becoming a platform input

EU AFIR requires publicly accessible alternative-fuels infrastructure operators/owners to make specified static and dynamic data available and expose an API. Delegated Regulation (EU) 2025/645 sets common API technical requirements and anticipates a common European access point.

Implication: Enigma should distinguish:
- commercial partner data;
- regulatory/open data;
- observed operational evidence;
- derived intelligence.

These sources have different authority, freshness, permissions, and liability.

### 2. OCPI is more modular than a simple version number

The official OCPI repository identifies 2.3.0 as the latest official release and separately packages optional modules such as Payments and Bookings. Its repository also describes Invoice Reconciliation in the 2.3.0 edition-2 development path.

Implication: an Enigma adapter must record **core version + module + edition + implementation profile**, not merely "OCPI 2.3".

### 3. OCPP reaches further into Enigma's future scope

OCPP 2.1 includes bidirectional charging, DER control, battery swapping, local cost calculation, ad-hoc payment and dynamic QR authorization.

Implication: Enigma's long-term energy/mobility model cannot treat charging as only a simple start/stop electricity session.

### 4. ISO 15118 changed in 2026

ISO 15118-20:2022/Amd 1:2026 was published in July 2026 and covers AC DER service, MCS service and improved security concepts.

Implication: Plug & Charge, megawatt charging and bidirectional/DER workflows need version-aware research rather than a frozen ISO 15118-20 assumption.

### 5. India privacy implementation is now materially more concrete

MeitY lists the Digital Personal Data Protection Rules 2025 and an enforcement timeline published in November 2025.

Implication: the India privacy model must be updated from "Act exists" to an implementation-aware compliance workstream.

## Strategic conclusion

The central unresolved problem is not connectivity alone.

Enigma must prove a residual gap after existing roaming hubs, eMSPs, CSMS platforms, OEM platforms, regulatory data APIs and direct provider integrations are combined.

The most credible research direction is therefore:

**provider-neutral transaction orchestration + evidence + policy + reconciliation across multiple existing networks and domains.**

This remains a hypothesis.

## Required next proof

Before building a broad platform, demonstrate one complete workflow with:

1. real provider permission;
2. real API/protocol interaction;
3. explicit authorization;
4. real transaction state;
5. money/reconciliation treatment;
6. evidence provenance;
7. failure recovery;
8. measurable customer value;
9. viable unit economics;
10. documented regulatory responsibility.
